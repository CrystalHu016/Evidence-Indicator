# Match Metrics 使用指南

## 如何查看Match Metrics

### 方法1: 执行新查询
1. 打开 http://localhost:8501
2. 从Sample Queries选择一个问题（例如："日本で梅雨がないのは北海道とどこか。"）
3. 点击查询按钮
4. 在结果页面会看到：
   ```
   📋 元のデータセット回答: 雨季
   
   ┌─────────────┬──────────┬──────────┬────────────┐
   │ マッチ率     │ 精度      │ 再現率    │ 完全一致    │
   │ 100.0%      │ 100.0%   │ 100.0%   │ ✅ はい     │
   └─────────────┴──────────┴──────────┴────────────┘
   ```

### 方法2: 查看历史记录
1. 打开 http://localhost:8501
2. 点击侧边栏的 "📚 履歴を表示" (Show History)
3. 在历史记录中，每个有dataset_answer的查询都会显示match metrics
4. 指标显示在dataset answer下方

## Match Metrics说明

### 🎯 マッチ率 (Match Rate)
- **100%**: 完美匹配！根拠と答え完全一致
- **80-99%**: 非常好，几乎完全匹配
- **50-79%**: 中等，部分匹配
- **<50%**: 需要改进

### 📊 精度 (Precision)
- **高精度 (>90%)**: 提取的内容很准确，几乎没有多余信息
- **中精度 (50-90%)**: 有一些多余信息
- **低精度 (<50%)**: 提取了很多无关信息

### 📈 再現率 (Recall)
- **高再现率 (>90%)**: 答案的内容基本都找到了
- **中再现率 (50-90%)**: 找到了答案的大部分
- **低再现率 (<50%)**: 答案的很多内容没找到

### ✅ 完全一致 (Exact Match)
- **✅ はい**: 100%精确匹配
- **❌ いいえ**: 不是完全匹配

## 实际示例

### 示例1: 完美匹配
```
クエリ: "日本で梅雨がないのは北海道とどこか。"
根拠: "雨季"
データセット回答: "雨季"

マッチ率: 100.0% ✅
精度: 100.0%
再現率: 100.0%
完全一致: ✅ はい

解释: 完美！提取的根拠和答案完全一致
```

### 示例2: 部分匹配
```
クエリ: "古今集と万葉集でより古いものは？"
根拠: "『古今集』の成立は『万葉集』よりも時代が下る"
データセット回答: "古今集"

マッチ率: 24.0%

解释: 答案(古今集)完全包含在根拠中，但根拠包含很多额外信息

再現率: 0.0%
完全一致: ❌ いいえ

解释: 根拠和答案完全不同，没有共同字符
```

## 何时显示Match Metrics

### ✅ 会显示的情况
- 查询来自sample queries
- 查询问题在merged_qa_dataset.json中存在
- 系统成功提取了根拠情報

### ❌ 不会显示的情况
- 自定义查询（不在数据集中）
- 没有提取到根拠
- 数据集中没有该问题的答案

## 技术细节

### 计算时机
- **新查询**: 在backend_integration.py中查询完成后立即计算
- **历史记录**: 在加载历史记录时动态计算（streamlit_app.py初始化时）

### 算法
使用Longest Common Subsequence (LCS)算法：
- 时间复杂度: O(m × n)
- 空间复杂度: O(m × n)
- m = 根拠の長さ
- n = 答えの長さ

## 故障排除

### Q: 历史记录中看不到match metrics
**A**: 确保：
1. 历史记录中的查询有dataset_answer
2. 历史记录中的查询有evidences数据
3. 前端已重启（刷新页面）

### Q: 新查询显示了metrics，但历史记录中没有
**A**: 
1. 进入履歴页面
2. 等待页面加载完成
3. metrics会自动计算并显示

### Q: Metrics显示0%但我觉得应该有匹配
**A**: 
- 检查根拠和答案是否使用不同的表达方式
- LCS算法要求字符完全相同且顺序一致
- 例如: "TPP" vs "環太平洋パートナーシップ協定" = 0% (完全不同的字符)
